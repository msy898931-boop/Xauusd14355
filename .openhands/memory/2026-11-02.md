## ⭐ biquote serves OHLC, not just a spot quote
`GET https://biquote.io/api/{symbol}/ohlc?interval=<tf>&limit=<1-1000>&from=&to=`
- `interval` ∈ {1m,5m,15m,30m,1h,4h,1d}. `limit` default 100, max 1000.
- Response `{"symbol","interval","bars":[{openTime,open,high,low,close,volume,tickVolume,isOpen}]}`,
  **newest bar first**, current bar tagged `isOpen:true`.
- `volume` is ALWAYS 0 (broker CFD, same trap as the tick) → use `tickVolume`.
- `x-robots-tag: noindex, nofollow` on the OHLC response.

**Depth is a retention ceiling, NOT the `limit`.** Raising `limit` past 1000 does
nothing, and `from`/`to` do **not** page deeper — they only *trim*. Measured max
bars per timeframe (2026-11-02):

| tf | bars | from → to |
|----|-----:|-----------|
| 1m | 301 | 11:45 → 16:45 same day (~5h) |
| 5m | 289 | 30 Oct 14:45 → now |
| 15m | 193 | 29 Oct 13:45 → now |
| 30m | 193 | 27 Oct 11:30 → now |
| 1h | 169 | 22 Oct 08:00 → now |
| 4h | 181 | 22 Sep 16:00 → now |
| 1d | 500 | 25 Mar 2025 → now |

So "كل الشمعات المتاحة" = ~5h of M1, ~4d of M5, ~6d of M15/M30, ~11d of H1,
~6w of H4, ~19mo of D1. The MT5 broker store is the limit; there is no deeper page.

## MarketDesk — the multi-agent desk (second build this day)
Owner asked for an agent-based market+news analyst: several agents, each with a
specialty + private memory + a shared memory that holds the biquote data source;
the orchestrator is central management. Built at **`/workspace/project/marketdesk/`**
(pure stdlib, no deps). Full run **~7 s** with Groq, **~3 s** keyless. 19 tests.

**Shape:** `orchestrator.gather()` pulls all biquote candles + quote into
`SharedMemory` (SQLite); `dispatch()` runs 8 agents concurrently; `synthesise()`
weights signed scores, applies the risk gate, builds the plan. Each agent =
one craft, one weight, a private `AgentMemory` JSON, and a `Study` published to
the shared `studies` table. Add an agent = subclass + one line in `ROSTER`.

**The 8:** structure (2.0) · trend (2.0) · levels (1.5) · news (1.5) ·
momentum (1.2) · risk gate (fail-closed) · volatility (0.8) · correlation (0.7).

**Two things worth remembering:**
1. **⭐ Groq rejects urllib's default UA with 403 `error code: 1010`** (Cloudflare).
   A browser-like User-Agent is REQUIRED — same wall as Kraken/gold-api/FF. This
   is why the first full run silently fell back to deterministic text: the LLM
   returned None and the agents narrated themselves. `llm.py` now sets the UA.
2. The **risk agent runs BEFORE synthesis and can veto** — `allowed=False` forces
   `no-trade` regardless of the weighted score. Fail-closed, never softened.

**Invariants enforced in code + tests:** every level tagged `pivot`/`fib`/
`projection`; an uncomputable metric is `None` never `0`; a source failure is
`[]` not an all-clear; the model narrates but cannot add a number.

Verified live: XAUUSD → `no-trade` (net −0.09, inside the neutral band);
XAGUSD → `short` with entry 50.99 / stop 51.18 / targets tagged pivot·pivot·fib.

### ⭐ Bug found on the first real "حلل" run — the gate was disarmed by a race
The first full analysis returned `allowed: True` while the news agent's own study
said `event_risk_24h: True` — the gate contradicted the evidence on the same
board. Cause: all 8 agents ran in ONE ThreadPoolExecutor. The risk agent reads
the shared SQLite **instantly**; the news agent waits on the **network**. So the
gate always won the race and read an empty `studies` row → waved through the
high-impact event it exists to block. A silent fail-OPEN in a fail-closed gate —
the worst kind, because the output looked fine.
Fix: `dispatch()` runs the **news agent FIRST, alone**, then the other 7 in the
pool. Owner's spec actually said this ("tell the news agent to gather + analyse
and send back" before the rest) — I had parallelised it away. Regression test
`test_news_runs_before_risk_gate` (20 tests now). Also made the no-trade note
name the exact reason instead of "either/or".
**Lesson:** when one agent's output is another's input, concurrency is a
correctness bug, not just a speed knob. Draw the dependency edge and serialise it.

### ⭐ Three real bugs the new instrumentation exposed
1. **The gate was a blunt instrument.** It blocked on *any* high-impact event
   within 24h — so every run died on an RBA decision 20h away. Fixed: the gate now
   needs the event (a) inside a short window (`DESK_EVENT_WINDOW_H`, 6h) **and**
   (b) in the *instrument's currency* (USD for gold). An RBA decision no longer
   blocks gold; JOLTS does.
2. **A losing plan was being stated.** First live `short` after the gate opened
   came with **R:R 0.56** — stop wider than reward. Now `min_rr` (1.5) is
   enforced. **Second-order trap:** my first fix took the nearest 3 levels and
   rejected them, which refused *every* setup (the nearest level is always too
   close). Correct fix: **walk the level list outward** and keep what pays.
3. **`max_tokens=800` silently killed model labelling.** `openai/gpt-oss-120b`
   is a reasoning model; 800 tokens is spent on the scratchpad and the answer
   comes back empty (3 failures, 0 content). 1500 completes. **A reasoning model's
   token budget must cover thinking *and* the answer.**

### ⭐ Bug #4: retrying a spent quota made the run 3x slower for nothing
Run time had drifted 7s → 22s. Cause was NOT the new labelling call: Groq's
**daily token quota (200k TPD) was spent**, so every call got `429`, and the LLM
client retried 3× with backoff on each of ~24 calls. The error body even said
`try again in 6m8s`. **A quota error is not transient — retrying cannot help.**
Fix: a **circuit breaker** on `429/402/403` that parses the provider's own
`try again in …` hint and short-circuits every later call. Run time back to 7.6s.
- The whole desk still works keyless; only the *prose* degrades to deterministic
  sentences. But the report was **silent** about it — a reader could not tell a
  computed line from a written one. Added an explicit warning line
  (`⚠ النموذج غير متاح (حد المعدّل) — النصوص أدناه حتمية`). **A fallback you don't
  announce is a lie of omission.**
- Diagnosing tip: a Groq call that fails in **0.1s** is a 4xx (quota/auth), not a
  timeout — print the HTTP status and body, don't guess.

### ⭐ Bug #5 (owner: "شوفلي موديل ثاني أفضل") — the answer was not "another model"
The owner asked for a better single model. The real finding: **Groq meters a
SEPARATE daily token quota per model.** Proven live — when `openai/gpt-oss-120b`
returned `429 "limit 200000 TPD"`, `gpt-oss-20b`, `qwen/qwen3.8-27b` and
`allam-2-7b` all answered fine in the same minute.
- So the fix is **not a better model, it is a chain**: `LLM` now takes a *list*
  and on `429/402/403` it **cools that model and rotates to the next** instead of
  dropping to computed prose. Only when the *whole* chain is cooling does
  `available` go False.
- Live proof: run 1 rotated 120b→20b (1 rotation); run 2 rotated 120b→20b→qwen
  (3 rotations). **The desk kept writing model prose through a spent quota.**
- Model quality check: hand-labelled 10 gold headlines (+1 bull / −1 bear).
  `gpt-oss-20b` and `qwen/qwen3.8-27b` both scored **10/10**. `allam-2-7b` (7B,
  Arabic-tuned) **cannot return the JSON** the labeller needs — keep it last, it
  is a fallback of last resort only. `120b` was quota-dead so unmeasured.
- Chain: `openai/gpt-oss-120b → gpt-oss-20b → qwen/qwen3.8-27b → allam-2-7b`.
  Override via `DESK_MODELS=a,b,c` (whole list) or `DESK_MODEL=x` (head only).
- The report now prints `↻ النموذج: … (دار N مرة)` so the reader always knows
  which model wrote the text. **A rotation is information, not noise.**
- Lesson: when a "pick a better one" request arrives, first check whether the
  options are actually **interchangeable resources** (separate quotas) rather than
  alternatives — a chain may beat a choice. 39 tests.

### Audit pass — four real defects, each found by measurement not inspection
The owner asked "what is missing for this to be excellent". Instead of listing
generic advice I audited the code and *measured* each claim.

**1. Indicators were fed the FORMING bar.** `frames_data()` returned every row
including the newest bar, which is still open — its h/l/c move with the tick, so
an indicator read off it is not a fact. Measured on live data: 1d RSI **38.0 with
the partial bar vs 30.8 without (Δ 7.2)**; 1h RSI 59.8 vs 65.1. Enough to flip a
reading. The `is_open` flag was already stored and carried into the reshaped bar
but **no consumer ever read it**. Fix: `frames_data()` filters `not r["is_open"]`;
new `Agent.live_price()` = quote if fresh, else last *closed* close. Levels and
risk agents now use it instead of `h1[-1]["c"]`.
**2. The neutral band was hardcoded 0.15 in 13 places** (orchestrator, every
agent, scoreboard). An agent's stance and the verdict could drift. Now one
`NEUTRAL_BAND` in `config.py` + `Settings.neutral_band` + `Agent.stance_of()`.
**3. The news comparison was unfair.** `keyword = classify(title + description)`
but the model got `f"{i}. {title}"` only. So the "13/25 disagreements" partly
measured *different inputs*, not different judgement. Both now get the same text.
**4. `budget_s` was a lie.** Proved with a 3s task and `budget_s=0.1`: it still
took 3.0s. `as_completed(timeout=None)` waits for the first *completion*, and
`result(timeout=remaining)` only bounds an already-done future. Replaced with
`cf.wait(futures, timeout=remaining)` — returns when the deadline passes, marks
overruns as timed-out. **A budget you cannot enforce is a claim, not a limit.**
**5. Correlation awarded a fixed 0.3 × weight = 0.21 whenever gold and USDJPY
moved opposite ways — regardless of whether they ever actually co-moved.** Now it
computes Pearson correlation of hourly returns and scales the score by the
measured rho (floor 0.2, else no vote). Live: rho ≈ 0.10 → correctly silent.
48 tests (was 39).

### P2 pass — the scoreboard was flattering itself
The biggest find was not a crash, it was a **measurement error that made the desk
look better than it is.**
**1. The scoreboard graded DIRECTION, not the plan.** A short that fell to its
target *after* first taking out its stop was counted a WIN. Now `_walk_plan`
walks the bars between the run and the horizon and reports the **first touch**:
`target` (win, worth the R multiple), `stop` (-1R, whatever came later), or
`open`. **An ambiguous bar (spans both) counts as the stop** — the conservative
reading that cannot flatter the desk. Summary now reports **expectancy in R**,
because a 60% win rate at 1.2R loses money and only the R average shows it.
New table `plan_outcomes`; `PLAN_HORIZONS` walks 5m to 4h and 15m to 1d.
**2. `database is locked` could surface as an agent failure.** 8 agents write
concurrently. Added `PRAGMA busy_timeout=30000` + `SharedMemory._write` (bounded
retry on "locked"/"busy" only) and routed **all 9 writes** through `_do_write`.
**3. mypy was not run at all.** Installed it; **36 errors in 8 files**. Most were
annotation noise (`per = {}` inferring `dict[str,str]`, `report = {...}` inferring
a union) but **one was a real bug**: in `correlation.py` the name `summary` was
used first as the payload dict and then reassigned to the narration string, so
`Study(summary=...)` was about to receive a dict. Renamed to `note`. Now
`mypy desk` → **Success: no issues found in 22 source files**.
52 tests (was 48).

### Running `serve` — and the one thing the agent cannot fix
`serve` is running in the background: `nohup python3 -u -m desk.cli serve
--interval 15 > data/serve.log 2>&1 &` (pid changes each restart; find with
`pgrep -f "desk.cli serve"`). The log gets one JSON line per pass:
`{"run_id":…, "verdict":"no-trade", "score":-0.129, "alerted":false,
"reason":"no directional call"}`.
**Secrets must be passed on the SAME command line that starts the process.**
`TELEGRAM_BOT_TOKEN`/`TELEGRAM_CHAT_ID` are injected by the harness into the
command's environment; a later command does not see them. Verified with
`tr '\0' '\n' < /proc/$PID/environ | grep -c TELEGRAM_BOT_TOKEN=`.
**`TELEGRAM_BOT_TOKEN` in this environment is INVALID: `getMe` returns 401
Unauthorized.** So alerts cannot be delivered until the owner sets a real token —
`Notifier.available` is True (both strings are non-empty) but `send()` returns
False. The desk stays silent, which is the designed behaviour, but the owner
would wrongly think alerting works. **Do not confuse "configured" with "working":
`available` only checks the strings are non-empty.** A `getMe` probe is the only
honest check, and it costs one API call.
- To rotate the token: Telegram → @BotFather → `/token` (or `/newbot`).
- To get the chat id: message the bot, then read `getUpdates`.

### Pushing to Xauusd14355 — blocked by the App install, not the token
Owner asked to push everything to `msy898931-boop/Xauusd14355` (empty repo,
default branch `main`). **Push failed 403, and the reason is NOT the token.**
Diagnosis (each step one API call):
1. `git push` → `remote: Permission to msy898931-boop/Xauusd14355.git denied to
   msy898931-boop` + HTTP 403. Note it denies the **owner's own name** — that is
   the signature of an integration, not of a missing user permission.
2. `GET /repos/{o}/{r}` → 200, `size: 0`, `push: true`. The *user* token has
   push on the repo. So the failure is not a repo-permission fact.
3. `PUT /repos/{o}/{r}/contents/.access-check` → **"Resource not accessible by
   integration"**. That phrase means a **GitHub App** is the actor, not a PAT.
4. `GET /user/installations` → one install, `app_slug: openhands-ai`,
   `repository_selection: selected`.
5. `GET /user/installations/169665685/repositories` → **total_count: 1**, and the
   only repo is `msy898931-boop/analysisdesk`. **Xauusd14355 is not in the list.**
**Root cause: the App is installed with "selected repositories" and the owner
never added Xauusd14355 to that selection.** GitHub's REST `/repos` view reports
`push: true` for the user regardless, so the API *looks* writable while the App
path is closed — the two views disagree and only the write probe is honest.
**Fix is owner-side, in the GitHub UI, not in code:** repo → Settings → GitHub
Apps → openhands-ai → grant access (or the App's installation settings page →
add the repository). Then the same push succeeds unchanged.
**Transferable rule: probe with a real write before trusting a permission
field.** `PUT contents` is the cheapest honest test; `/repos` and `permissions`
are advisory. Also: `x-oauth-scopes` being **empty** means a fine-grained token
or App token, not a classic PAT — another hint the App is the actor.
Commit was made locally regardless (`831c6fc`, branch `main`, 46 files, secret
scan clean) so the push is a one-liner once access is granted.

### ⭐ Live defect found by reading the data, not the code: the ledger lied
`signal_ledger.json` held `{"XAUUSD:short:-0.3": "85b5085d6574"}` while run
`85b5085d6574` itself logged `"alerted": false`. **The two facts contradict** —
an entry in the ledger means "delivered", the run says "not delivered".
Cause: `watch_once` called `ledger.record()` **unconditionally** after `send()`.
A failed send was therefore recorded as alerted and **suppressed forever** — the
next pass returned "already alerted" and never tried again. Silent, permanent.
Fix: record only when `sent` is True, so a failure retries next pass.
Regression test added; **verified by mutation** (reintroduce the bug → test
fails; restore → passes). 53 tests.
**The transferable lesson: cross-check two records that must agree.** Neither
the code nor the tests revealed this; the ledger and the run row disagreed.
A "poisoned" ledger entry was moved aside (`signal_ledger.json.bak-poisoned`),
not deleted, so the evidence survives.
